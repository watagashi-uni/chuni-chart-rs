# 短 HOLD：头部窗口与尾部 MISS

为避免短 HOLD 的延后色带误导操作，判定图将普通和 EXT HOLD 的显示范围截到尾部时刻。以下记录对 `2147_03` 及 2.40、2.50 EXE 的静态核查，说明显示裁剪与游戏内部头部窗口的区别。

## 实谱定位

`2147_03` 的 BPM 为 180、RESOLUTION 为 384。C2S 第 393–404 行、位置 `32:288`、`32:336` 和 `33:0` 的 HOLD 长度都是 6 ticks，即 1/64 小节、20.833333 ms。全谱共有 33 条 6-tick HOLD，另有两条 1-tick HOLD。

以第 393 行为例：

| 数据 | 值 |
| --- | --- |
| 头部时刻 | 43.666666667 s |
| 尾部时刻 | 43.687500000 s |
| 默认头部延后 JC 外边界 | 43.700000000 s（+33.333333 ms） |
| 默认头部延后 JUSTICE 外边界 | 43.733333333 s（+66.666667 ms） |
| 默认头部延后 ATTACK 外边界 | 43.750000000 s（+83.333333 ms） |

解析得到的 HOLD 时长正确；内部头部后窗超过尾部 62.5 ms。出图时，此例延后 JC 截到 +20.833333 ms，后续 JUSTICE / ATTACK 色带及其边缘阴影不再绘制。

## EXE 中是两套结算状态

| 行为 | 2.40 地址 | 2.50 地址 |
| --- | --- | --- |
| 每帧先更新头部、再更新持续段 | `0x00C0F8F0` | `0x00C4F6A0` |
| 头部输入候选登记 | `0x00C0E080` | `0x00C4DD90` |
| 头部结果结算 | `0x00C0E770` | `0x00C4E4D0` |
| 头部通用输入接受检查 | `0x00BFF940` | `0x00C3F0A0` |
| 头部窗口初始化 | `0x00D5EF40` | `0x00C3C970` |
| 持续段／尾部检查点结算 | `0x00C0E0C0` | `0x00C4DDD0` |
| KEEP 输入状态更新 | `0x00D5FEF0` | `0x00C3D940` |
| 头部与持续段都结束才退出 | `0x00C0EF50` | `0x00C4ECC0` |

2.50 的对象 `+232` 是头部状态，`+236` 是持续段状态。头部候选和结果函数只检查 `+232` 是否已经完成，不以 `+236` 完成或 HOLD 尾部时间为截止条件；窗口初始化也没有以 HOLD 时长裁剪后窗。2.40 对应字段为 `+212/+216`，逻辑相同。

持续段在检查点时刻读取 KEEP 状态。2.50 的 `0x00C3D940` 记录是否曾有有效按住输入；`0x00C3C660` 在从未按住时返回失败档，`0x00C4DDD0` 的检查点分支将其映射成 MISS，并移除已经结算的检查点。之后按下头部不会重算该检查点。

因此，静态代码支持这样的情形：尾部已经在无输入状态下结算 MISS，稍后一次输入仍能获得头部的 JC／JUSTICE／ATTACK。看到头部判定范围不代表持续段可以补救；用户报告的尾后按下仍出现 MISS 与此一致。

## 显示规则

在完整计算相邻保护之后，绘图阶段将 HOLD 头部的延后范围取 `min(内部后窗, 尾部时刻 − 头部时刻)`。使用经过 BPM 分段积分的实际尾部时间；普通 HOLD、HXD 及被 EXT 覆盖的 HOLD 头均适用，零长度 HOLD 只保留提前部分。色带和边缘阴影使用相同的裁剪范围。

提前范围、相邻音符的保护和普通谱面图不变；长 HOLD 不会扩展原本的后窗。行尾 `HLD` 样式的 SLIDE 仍是 SLIDE，不应用此规则。Fastattack 原本只显示提前部分，效果不变。

这是一项显示约定，不是对 EXE 头部判定的重新定义，也不模拟持续段完整状态机。`inspect` 和 `judgement::protect*` / `bands` 数值 API 继续保留内部窗口。

以上是静态逆向结论，没有运行游戏逐帧实测。尾部检查受每帧采样、判定偏移及 KEEP 状态影响，不能把 20.833333 ms 当成精确到任意亚帧输入的绝对截止时间；相邻音符的输入竞争也仍是独立条件。EXE 哈希见 [C2S 变速与 SLIDE 样式](c2s-scroll-slide.md)。
