# C2S 变速与 SLIDE 样式

依据本地 `chusanApp.exe` 的 IDA MCP 静态分析。EXE SHA-256：

```text
77ad8c04046ac895fc777a5eb66e6c6f23bd5a6bbf1dbb11f7b2f64adaba1123
```

上面的 EXE 用于变速规则分析；SLIDE 部分另列 2.50 EXE 的哈希与地址。所有地址均为对应 PE 的虚拟地址。仓库只保存格式结论和自制测试，不包含游戏二进制或实谱。

## SFL、SLP 与 SLA

```text
SFL measure tick duration velocity
SLP measure tick duration velocity profile_id
SLA measure tick lane width duration profile_id
```

`0x011A8B60` 的 SFL 分支以编号 0 调用速度列表插入函数，SLP 分支从第 6 列读取编号后调用同一函数（实际实现 `0x011AABD0`）。因此 `SLP ... 0` 与 `SFL` 进入同一全局程序，无须额外 SLA。旧实现仅处理被 SLA 引用的 SLP，导致只有 SLP 0 的谱面不显示变速标记。

SLA 选择一批音符使用哪个程序，其时间范围与 SLP 的速度变化时间独立。音符判定时刻之前发生的速度变化也会影响音符接近判定线时的运动，不能把速度程序裁成 SLA 的时间交集后当作原始数据。

`0x011A1FD0` 的选择规则：

- 时间加 `1/192` 个四分音符拍（`RESOLUTION / 768` ticks）后，落在 SLA 的左闭右开区间内。
- 音符的整个横向范围必须包含在 SLA 中，部分重叠不匹配。
- 多个区域匹配时取最大的正列表编号；无匹配时为 0。

库中的 `scroll_profiles` 保留所有程序及原始分段（包括未引用和零时长记录），`scroll_areas` 保留区域，`Chart::scroll_profile_at` 提供上述位置查询。该查询针对单个音符/节点，不表示一条长条全部节点采用同一程序。`scrolls` 保留静态预览的标记接口，并带有 `profile_id` 和可选的区域索引 `area`。重复引用同一程序的区域可分别绘制；区域编号 0 不重复绘制全局标记。

本项目按真实时间输出静态谱面，变速绘制为标记，不模拟游戏运动、倒退或停顿后的物理位置。区域标记沿用原预览对程序时间的展示方式；准确的音符选择范围以 `scroll_areas` 为准。

## DCM、STP 与未知记录

2.50 EXE（哈希见下节）的 `0x011FBD60` 确认以下格式：

```text
DCM measure tick duration multiplier
STP measure tick duration
```

`DCM` 是记录编号 19（注册于 `0x0052BF3D`）。分支 `0x011FC0A3` 和 `SFL` 分支一样，从索引 1、2 读取起点，索引 3 读取持续 ticks，索引 4 读取浮点倍率；终点为起点加持续 ticks，并经过同一时间转换。它最终在 `0x011FC13A` / `0x011FC14D` 追加到容器 `+0x20` 的独立列表，没有加入 SFL / SLP 的编号程序。因此本项目保存为独立的 `distance_scrolls`，在轨道右侧显示 DCM 区间和倍率；SFL / SLP 全局标记仍在左侧。极小倍率使用科学记数法，避免把 `0.000001` 显示成 `0.00`。标记只说明源记录，不模拟动态运动，也不改写 BPM、音符时间或判定窗。

`STP` 的编号 15 分支 `0x011FBE70` 将倍率置零，再进入与 SFL 相同的全局程序插入函数；本项目等价解析为 `SFL ... 0`。

`CLK` 和未知记录跳过，与原项目忽略未支持记录的兼容策略一致。未知记录不会被猜测为音符或变速。已支持的音符、BPM、拍号和变速记录仍校验字段，NaN、无穷大、负持续时间和资源超限仍失败。合法大 BPM、细拍号（例如 1/384）及大变速倍率不再因原来的任意小上限而失败；事件、拍线、持续时间、图片和进程限制继续生效。

## SLIDE 样式：兼容 2.50 与旧版谱面

此节依据用户提供的 2.50 `chusanApp.exe`。其调试路径包含 `v2_50`，SHA-256：

```text
09b4e88d4ce8abdaddb987f0b371e86a66a14751a09c934ae3ac733c94d9d0e9
```

样式是 `SLD/SLC/SXD/SXC` 的可选第 9 列，与记录开头的音符关键字、末尾 EXT 头的形状字段分开：

```text
SLD 0 0 4 4 384 8 4 NCL
SXC 0 0 4 4 192 8 4 NCL UP
```

`0x011FA510` 读取索引 8 的字段，交给 `0x01204370` 转换；`0x01C26E50` 的样式表只有两个值：

| 输入 | 枚举值 | 绘制 |
| --- | ---: | --- |
| SLD | 0 | 普通 SLIDE，含中线 |
| NCL | 1 | 同一 SLIDE 本体，关闭中线 |
| 省略、未知值 | 0 | 回退为普通 SLD |

2.40 的旧表含 `SLD/HLD/GRN`，不能据此推断 2.50 的新特性。2.50 不再在这个样式表中识别 `HLD/GRN`；本项目为兼容旧谱，额外识别这两种旧样式，不按 2.50 EXE 将其回退。这不影响行首 `HLD` 的普通 HOLD，也不影响 AIR 颜色字段中的 `GRN`。

2.40 的旧样式可以通过 EXE 的 `0x01BB4F68`、本地 `data/db/TextureTableRecord.bin` 和实际 DDS 纹理交叉确认：

| 旧样式 | 轨迹纹理 | 中线纹理 | 轨迹外观 |
| --- | --- | --- | --- |
| SLD | 1 / `chu_notes_slidejoint_v10.dds` | 2 / `chu_notes_slide_line_v10.dds` | 普通蓝青色，有中线 |
| HLD | 0 / `chu_notes_holdjoint_v10.dds` | -1 / 不绘制 | HOLD 的黄橙色轨迹，无中线 |
| GRN | 5 / `chu_notes_airhold_slidejoint_v10.dds` | 6 / `chu_notes_slide_line.dds` | 绿色轨迹，有绿色中线 |

旧 HLD 样式的轨迹纹理确实为黄橙色，不能称作蓝色 NCL；旧 GRN 也确实更换了轨迹和中线纹理，而非仅根据名称猜测颜色。两者都仍是 SLIDE 记录，样式与音符类型分开。本项目以已有矢量绘图风格实现这两种旧外观：HLD 共用普通 HOLD 的黄橙色轨迹填充，GRN 使用绿色填充和独立绿色中线；EXT 头仍为金色，判定类型与时刻不因样式改变。

### 数据流和绘制依据

- `0x011FC8A0`：四种 SLIDE 记录共用样式解析；连接时在 `0x011FCD8C` 比较对象 `+168` 的样式值。样式不同的段不连接，EXT 头标志独立保存。
- `0x00B3E1A0`：轨迹资源列表统一为 `0x01C1CFC0` 的三个资源 `1/2/3`；在 `0x00B3EBF8` 读取样式，并传入绘制描述的 `+48` 字段。
- `0x00C27170` 调用 `0x00C24780` 复制描述；样式最终保存在 `JointSlide` 对象 `+64`。
- `0x00C2E550`：先正常生成轨迹，在 `0x00C2F6E4` 检查样式是否为 1；NCL 跳过中线网格生成。轨迹本体和末端分支没有按 NCL 换色或换成 HOLD。
- `0x00C347B0`：普通头和 EXT 头仍走各自既有资源路径，不因 NCL 改成另一种判定类型。

本项目使用已有的矢量绘制风格，不复制游戏纹理。NCL 仅移除中线，保留 SLD 的轨迹配色、普通端点和金色 EXT 头；不会涂成 HOLD 的黄橙色，也不会给 NCL 额外指定与 SLD 不同的整条纯色。`inspect` 的头、尾和长条保存 `slide_style: "NCL"`，判定类型、BPM 和时刻保持原有规则。

连续 SLIDE 的本体和中线各合并成一个轮廓填充，避免每段独立抗锯齿在内部边界留下横缝。连接仍按时刻、位置、宽度和样式匹配，终止段之后开启新的渐变；保留真实转折，仅移除共线的冗余采样点。渐变按整条轨迹的 ticks 计算，BPM 变化作为渐变节点，不需要重新拆分几何轮廓。

## 验证

`tests/scroll_slide.rs` 使用自制谱面覆盖：SFL 与 SLP 0 的完整解析/图片等价性、跨 BPM 的时间转换、SLA 起止边界与完整包含条件、重叠优先级、独立程序时间、无效编号与时长、SLD/NCL/HLD/GRN 解析及 inspect 字段、未知样式回退、四种样式的所有连接组合和重叠去重，以及普通/判定/fastattack 三种图中的像素对照：NCL 仅移除中线，HLD 为黄橙色无中线，GRN 本体和中线为绿色，EXT 头保持金色。普通 HOLD 的配色也独立验证。HTTP 冒烟测试用包含全部四种 SLIDE 样式和普通 HOLD 的自制谱面比对 CLI 和服务出图。

用户提供的 `3014_03.c2s`（格式版本 `1.15.00`）含 186 条 NCL 记录：SLD 56、SLC 24、SXD 74、SXC 32；其他 449 条 SLIDE 为普通 SLD。实谱和游戏二进制不加入仓库。

DCM / STP 的自制回归另覆盖跨 BPM 的区间转换、独立程序数据、三种模式中的倍率标注、零时长记录保留、无效字段拒绝；未知记录测试确认 CLK / 新记录不会改变已知谱面数据，合法大数值和密集谱面测试同时检查资源预算仍然生效。图片只显示倍率，不添加 `DCM` 字样。

2026-11-03 的 v0.2.8 本地全量验证：14,223 份 C2S 全部解析成功；普通、判定、Fast ATTACK 各 14,223 次，共 42,669 次 PNG 出图全部通过。每个进程限制 256 MiB 地址空间、12 秒 CPU、15 秒墙钟；校验 PNG 尺寸、字节上限和块校验和后释放临时图片，仅保留统计结果。Rust 测试及 HTTP 冒烟、安全回归通过。本次没有新增 QQBot 用户文本回显，展示的是结构化谱面数值。

接缝修复另由 `tests/slide_seams.rs` 比较整段与细分后轨迹的最终像素，覆盖四种样式、三种出图模式、三档 zoom、自动缩图、跨 BPM、弯曲变宽、跨列及越界裁剪，并确认终止段的渐变不会串接。`malleus` 截图同一位置的接缝已消除；7 张代表谱面的三种模式共 21 次出图在上述进程限制内通过，57 项 Rust 测试和 HTTP 冒烟、安全回归通过。此修复仅涉及绘制，没有新增 QQBot 用户文本回显。
